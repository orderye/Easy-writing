## 二、分阶段量测

### 阶段 1 · 测试覆盖缺口

| 项 | 前 | 后 |
|---|---:|---:|
| `command_key_sweep` handler 注册数 | 63 | **77** |
| `command_key_sweep` 用例数 | 63 | **77** |
| `ipc_argcase` 命令数断言 | 77 | **85** |
| 测试文件数 | 4 | **5** |

**发现的真实问题**：`command_key_sweep` 的注释写着「Keep the handler list and
`cases` in sync when commands are added」，但它自身已经失同步——新增的 6 个对话命令、
`update_llm_profile`、`fetch_remote_models` 全都不在其中。也就是说，
上一轮「修复差异报告」新增的命令**当时处于无测试守护状态**。

**受限说明**：`ai_chat_stream` / `save_chapter_content` / `save_image_asset` /
`webdav_backup_now` / `webdav_restore_backup` 的首参为 `tauri::AppHandle`，
而 `AppHandle` 不实现 `CommandArg<'_, MockRuntime>`，因此**无法**在 MockRuntime
下注册，本 sweep 覆盖不到，已在测试中显式注明并由 `ipc_argcase` 兜底。
这是测试框架的客观限制，不是配置疏漏。

### 阶段 2 · db 层 mapper 消重

| 指标 | 值 |
|---|---:|
| db 目录净变化 | +421 / −460 = **净 −39** |
| 新增 `mapper.rs` | 51 行 |
| 消除的「同 mapper 复制两份」处 | 16 个实体函数 |
| 消除的 `rows.next()` 三段式 | ~30 处 |
| 消除的 `Vec::new()+push` 收集循环 | ~20 处 |

**注意**：本阶段的行数收益（−39）远小于方案预估的 ~300 行。原因是方案预估时
把「同一实体 list/get 两份 mapper」按整段重复计算，实际其中一份本就要保留为
共享函数，净删主要来自三段式与收集循环。**真正的收益不在行数，而在语义**：
列清单提取为常量后，SQL 的 SELECT 顺序与 `row.get(n)` 的下标绑定在一处，
杜绝了「改了 SELECT 忘了改下标」这类静默错位——这类 bug 编译期不报错、
运行期只在特定行显现，是 db 层最难查的一类。

### 阶段 3 · IPC 调用构建器

| 指标 | 值 |
|---|---:|
| 前端整体净变化 | +1508 / −1904 = **净 −396** |
| 删除参数结构体 | **79 个** |
| 迁移调用点 | **120 处** |
| 覆盖文件 | 25 个 |
| 新增 `tauri_api` 构建器 | 92 行 |

**方案偏离说明（重要）**：方案原定用 `macro_rules!` 展开字段表
（`invoke_cmd!("cmd", { a, b: expr })`）。实测发现两个无法绕过的障碍：

1. **片段匹配歧义**：`$v:expr` 后不能直接跟 `,`，导致
   `{ novel_id, term: t, category: cat, source_id: None }` 这类
   简写与显式键名混排的字段表无法被单一规则匹配。
2. **裸 `None` 无法推断类型**：`to_value(&None)` 缺少 `Option<T>` 的 `T`，
   编译报 `E0282：type annotations needed`。

我写了一个独立探针（现 `tests/ipc_arg_encoding.rs`）逐形状验证，
确认这是宏机制的固有限制而非写法问题，最终改用链式构建器：
类型推断回归普通 Rust 规则，无歧义；`.opt()` 显式表达可选语义。
**这是本次实施中唯一偏离原方案的设计决策。**

### 阶段 4 · 拆分 `config_modal.rs`

| 文件 | 行数 | 职责 |
|---|---:|---|
| `config_modal.rs` | **948** | 外壳：标签栏 + 分发 |
| `agent_tab.rs` | 129 | 多 Agent 接口绑定 |
| `prompt_tab.rs` | 114 | 修饰提示词模板 |
| `webdav_tab.rs` | 261 | WebDAV 整库同步 |
| `pref_tab.rs` | 199 | 写作偏好 |
| `app_settings.rs` | 27 | 偏好读写公共入口 |
| `update_modal.rs` | 161 | 关于与更新（原有） |
| `mod.rs` | 7 | 模块注册 |
| **合计** | **1846** | 原单文件 1560 |

**关键结论：本阶段行数增加（+124），但这是刻意的。** 去繁化简的目标不是行数
最小化，而是让每个文件只承担一个域的职责。拆分前 1560 行里塞了 6 个不相关域、
39 个 `RwSignal` 平铺在同一作用域；拆分后最大文件降到 948 行（外壳），
各标签页状态内聚。

顺带修掉一个真实缺陷：原先切到「写作偏好」再点保存，会把**当前所有标签页的信号**
一起写库；拆开后每个标签页只持有自己的状态，副作用范围收敛。

`ipc_argcase::every_command_declares_snake_case` 把命令数钉死为 77，
失败信息为「command count changed — re-audit the frontend call sites」。
阶段 1 补齐覆盖后命令数变为 85，该断言**如期失败**。

这是**守卫按设计工作**，不是回归。处置方式是逐条审计新增的 8 个命令
（6 个对话记录 + `update_llm_profile` + `fetch_remote_models`）
确认均带 `rename_all = "snake_case"`，再更新断言并附审计说明——
**没有绕过或禁用该断言**。

## 五、结论

本次优化的实际收益，按重要性排序**不是行数**：

1. **消除了一类静默 bug**（阶段 2）：SQL 列序与 `row.get(n)` 下标绑定在
   mapper 常量一处，不再可能错位。
2. **消除了契约漂移的温床**（阶段 3）：86 个参数结构体是后端 snake_case 契约的
   第二份手抄，删掉后键名与值写在一处，不再有「抄错键名到运行时才暴露」的路径。
3. **收敛了副作用范围**（阶段 4）：标签页拆分让每个域只持有自己的状态，
   「保存偏好却写入全部标签页状态」这类越界副作用不再可能。
4. **补上了缺失的自动防线**（阶段 1）：8 个此前无测试守护的命令进入 sweep。

净删 343 行是这些结构性改进的副产品，而非目标本身——阶段 4 甚至主动增加了
124 行以换取职责清晰。
