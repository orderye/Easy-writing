### 3.1 测试编写过程中发现的三个真实问题

这些不是「测试写错了」，而是测试暴露出的实现缺陷，均已修复：

| 发现 | 问题 | 处理 |
|---|---|---|
| `rejects_zip_bomb_entry` 失败 | 上限确实生效了（48 MiB 没进内存），但错误被 `continue` 吞掉，作者看到的是「文件可能已损坏」这种误导性提示 | 引入 `EntryReadError` 强类型，超限与损坏分流；超限中止整个导入并指明是哪个文件 |
| `empty_trash_is_all_or_nothing` 失败 | 测试前提错误：`soft_delete_novel` 只级联 novel/volume/chapter，不含设定表 | 修正测试前提并加前置断言；顺带把这个「删除作品不清设定」的行为事实记录进注释 |
| `preflight_rejects_non_sqlite_payload` 失败 | 断言过于具体：SQLite 延迟打开，字节流能 open 但过不了 `integrity_check` | 断言改为「必须被拒绝」+ 覆盖两条拒绝路径 |

**另外在自查中发现版本门禁自身的缺陷**：初版只解析 `--tag=v0.3.8`，
而 CI 里是 `--tag "$TAG"`（空格形式），导致**错误 tag 反而通过检查**。
已修复并实测验证错误 tag 被拦截。

### 7.4 测试编写过程中发现的四个真实缺陷

这四条都是**测试跑出来的**，不是代码审查推断，均已修复：

| 发现于 | 缺陷 | 后果 | 处理 |
|---|---|---|---|
| `rotation_only_deletes_managed_backups_over_real_http` 首次失败 | 轮转只删 `.db.gz`，`list_files` 从不返回 sidecar，因此**清单永远不会被删** | 每轮转一次就在用户 WebDAV 上留一份孤儿 `.json`，且无任何后续机制清理，远端目录无限膨胀 | `prune_remote_backups` 删备份时一并删 `<path>.json` |
| `rollback_helper_rejects_missing_snapshot` 失败（返回 Ok） | `Connection::open` 对不存在的文件会**新建空库**，随后 Backup API 用这个空库覆盖目标库 | 「快照丢失」→「数据被清空」：回滚本身变成数据销毁 | 回滚前显式检查文件存在 + 复用 `preflight_backup` 验证快照可用 |
| 构建 P0-3 弹窗时排查 CSS | `z-60` 在 Tailwind v3 下**不生成任何 CSS**（默认刻度只到 50），仓库里有 4 处破坏性确认弹窗用了它 | 类名写在那里、代码看着正常，但弹窗拿不到预期层级 | 全部改为 `z-[60]`（实测生成 `.z-\[60\]{z-index:60}`），并加全仓护栏用例 |
| `webdav_backup_now` 契约梳理 | 后端已有 `verified` / `manifest_uploaded` / `image_upload_failures`，command 层只回传 filename | 清单没传上、图片没同步、素材本地就缺，全部消失在 IPC 边界 | 返回类型改为 `BackupReport` |

另记录一项**瞬时故障**（非代码缺陷）：`bundle_dmg.sh` 首次构建失败、
无改动重跑即成功，且失败会遗留挂载卷 + 46 MB 的 `rw.*.dmg`。
已加 `scripts/tauri-build-retry.sh`（本地实测 exit 0，未误伤正常构建）。

### 7.5 护栏不空转的自证

`z_class_guard_is_not_vacuous` 用合成字符串验证检测逻辑本身：
必须能取出 `z-50` / `z-60` / `z-[60]` 三个类名、不能误吞 `maximize-3` 的尾巴，
并且必须判定 `z-60` 未生成 CSS 而 `z-[60]` 与 `z-50` 已生成。

这是为了防住护栏类测试最常见的两种失效：
扫描逻辑匹配不到任何东西，或 CSS 查找恒为真 —— 两者都会让用例永远绿。

### 7.6 本轮的签名与契约变更（编译期强制）

```
manifest::build_manifest(conn, app_version, size)              → (conn, app_version, size, sha256) -> Result<_, String>
manifest::reconcile_with_disk(&mut m, dir) -> Vec<String>      返回值现在被真实使用并写入 m.missing_assets
manifest::MANIFEST_VERSION                                     1 → 2（MIN_SUPPORTED 保持 1，v1 清单仍可解析）
backup::cross_check_manifest(path, report)                     删除（其前提「读本地临时库旁的 sidecar」即缺陷本身）
restore::run_consistency_restore(..)                            + preflight_token, confirm_empty_overwrite, hooks
sync_cmd::webdav_backup_now -> Result<String, _>               → Result<BackupReport, _>
```

去掉 `RestoreReport::default()` 是有意的：构造一份恢复报告时**必须**声明结局，
不能靠默认值悄悄返回一个看起来像成功的空报告。
