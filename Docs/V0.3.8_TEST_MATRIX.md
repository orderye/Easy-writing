### 3.1 测试编写过程中发现的三个真实问题

这些不是「测试写错了」，而是测试暴露出的实现缺陷，均已修复：

| 发现 | 问题 | 处理 |
|---|---|---|
| `rejects_zip_bomb_entry` 失败 | 上限确实生效了（48 MiB 没进内存），但错误被 `continue` 吞掉，作者看到的是「文件可能已损坏」这种误导性提示 | 引入 `EntryReadError` 强类型，超限与损坏分流；超限中止整个导入并指明是哪个文件 |
| `empty_trash_is_all_or_nothing` 失败 | 测试前提错误：`soft_delete_novel` 只级联 novel/volume/chapter，不含设定表 | 修正测试前提并加前置断言；顺带把这个「删除作品不清设定」的行为事实记录进注释 |
| `preflight_rejects_non_sqlite_payload` 失败 | 断言过于具体：SQLite 延迟打开，字节流能 open 但过不了 `integrity_check` | 断言改为「必须被拒绝」+ 覆盖两条拒绝路径 |

**另外在自查中发现版本门禁自身的缺陷**：初版只解析 `--tag=v0.3.8`，
而 CI 里是 `--tag "$TAG"`（空格形式），导致**错误 tag 反而通过检查**。
已修复并实测验证错误 tag 被拦截。

## 5. 手工执行的检查

```
$ node scripts/check-version.mjs

  src-tauri/Cargo.toml       0.3.8
  shared-types/Cargo.toml    0.3.8
  frontend/Cargo.toml        0.3.8
  src-tauri/tauri.conf.json  0.3.8
  CHANGELOG.md                  ✅ 含 [0.3.8] 条目
版本一致性检查通过。  EXIT=0

$ node scripts/check-version.mjs --tag v0.3.7     # 故意用错 tag
❌ 错误：发布 tag 版本不匹配：tag = v0.3.7（即 0.3.7），但构建配置版本 = 0.3.8。
版本一致性检查未通过（1 项错误）。  EXIT=1
```

**门禁有效性已实测验证**：错误 tag 确实被拦截。

自查中发现并修复了一个真实缺陷 —— 初版只解析 `--tag=v0.3.8`（等号形式），
而 CI 里写的是 `--tag "$TAG"`（空格形式），导致错误 tag 反而通过检查。
现已同时支持两种写法。

## 6. 回归保护说明

本次**未删除、未跳过、未弱化任何既有测试**。所有既有测试文件与用例保持原样，
仅在 `epub_import.rs` 与 `novel_trash.rs` 中**追加**了新用例。

唯一的行为签名变更是：

```
db::trash::purge_trash_item(&Connection, ..) → (&mut Connection, ..)
db::trash::empty_trash(&Connection, ..)      → (&mut Connection, ..)
```

这是事务化的必要条件（`rusqlite::transaction()` 需要独占引用），
属编译期强制，调用方已在 `commands/mod.rs` 与 `novel_trash.rs` 同步更新。
