### 1.2 CI 阻断项：lockfile 不一致 ✅

**证据**：本地 `CI=true pnpm install --frozen-lockfile` 通过（exit 0）。

### 1.4 WebDAV 镜像钉版后的 CI 重跑：发现并修复真实回归 ✅

ci.yml 已由 `latest` 钉到 `ghcr.io/hacdias/webdav:v5.17.3`，并 echo 实际镜像 ID。

**CI run `45853862877`**（HEAD `7fac606`，2026-11-26）：6 个 job 的**结论均为 success**，
但逐行审计日志发现 WebDAV job 内部 `cargo test --test webdav_real_server` 实际输出为
`test result: FAILED. 1 passed; 2 failed`，因 step 末尾的容错处理使 job 整体仍显示成功。
**不能把该 run 记为 WebDAV 通过。**

| 检查项 | 实际结果 |
|---|---|
| 固定标签生效 | ✅ 日志确认 `WebDAV 服务端镜像：ghcr.io/hacdias/webdav:v5.17.3`，实际镜像 ID `sha256:3b70d2a3…` |
| PROPFIND 探测 | ✅ HTTP 207，服务就绪，鉴权正常 |
| `real_server_rejects_wrong_credentials` | ✅ 通过 |
| `real_server_backup_and_restore_roundtrip` | ❌ `无法创建远程目录 ew-it-…: HTTP 403 Forbidden` |
| `real_server_reports_missing_manifest_as_not_found` | ❌ 同为 MKCOL `HTTP 403 Forbidden` |

**判断**：这是钉版引入的兼容性回归。上游 README 明确写 `permissions` 默认值为
`R`（只读）；旧版 `latest` 默认值更宽松，钉到 `v5.17.3` 后未显式配置，
MKCOL 创建测试目录返回 403。此前 `latest` 运行的通过证据不能沿用。

**已实施修复（提交 `50ec8bd`，双远程已推）**：
1. `config.yml` 全局与用户级均显式配置 `permissions: CRUD`，覆盖 MKCOL/PUT/MOVE/DELETE；
2. 测试 step 加 `set -o pipefail`，让 `cargo test` 的失败不再被 `tee` 吞掉，
   WebDAV 用例失败时 job 会**真正变红**，消除"绿灯下的失败"。

**验证结果：CI run `45854806441`（HEAD `50ec8bd`）全绿，逐行审计确认真实通过**：

| 检查项 | 结果 |
|---|---|
| 6 个 job 结论 | ✅ 全部 `success` |
| 固定标签 | ✅ `ghcr.io/hacdias/webdav:v5.17.3`，镜像 ID `sha256:3b70d2a3…` |
| `real_server_backup_and_restore_roundtrip` | ✅ `verified=true, manifest_uploaded=true, 图片失败=0` |
| `real_server_rejects_wrong_credentials` | ✅ 错误凭据被拒绝 |
| `real_server_reports_missing_manifest_as_not_found` | ✅ 缺失清单返回 404 |
| WebDAV job 测试汇总 | ✅ `test result: ok. 3 passed; 0 failed`（pipefail 保证失败不会被吞） |

> 说明：早先的 run `45854039838`、`45854203478` 虽也显示 success，但均未加 `pipefail`，
> 其 WebDAV 用例在钉版后实际为 2 failed（被 `tee` 吞掉）。**只有 `45854806441` 是可信的
> 钉版通过证据**；验收文档应以此 run 为准。
