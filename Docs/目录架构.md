# Easy-writing 目录架构与数据分布地图

> 维护于 2026-11-03 目录整理。回答两个问题：**每个目录为什么存在**、**各类数据落在哪里**。
> 整理动因：构建缓存 56GB、160MB 历史发布产物、活库中 3 份重复导入的测试小说（76 万行词库）把项目数据挤得过于分散。

---

## 一、仓库顶层结构

| 路径 | 职责 | git 跟踪 | 备注 |
|---|---|:---:|---|
| `src-tauri/` | 后端 crate **easy-writing-core**（Tauri 命令、DB、导入、AI 提炼、备份/WebDAV） | ✅ | workspace 成员；`migrations/` 放 V001–V009 迁移阶梯 |
| `frontend/` | 前端 crate **easy-writing-frontend**（Leptos 0.7 CSR → WASM） | ✅ | workspace 成员；`dist/` 为 trunk 构建产物（gitignore） |
| `shared-types/` | 前后端共享类型 crate **shared-types** | ✅ | workspace 成员 |
| `js/` | Tiptap 桥与角色图桥的原生 JS 源 | ✅ | esbuild 打包到 `frontend/public/*.bundle.js`（`pnpm build:bridge`） |
| `tests/` | JS 契约测试（`node --test`） | ✅ | `frontend/` 12 个 + `scripts/` 3 个，见 §二 |
| `scripts/` | 运维 CLI：`check-version.mjs` / `check-docs-schema.mjs` / `release-gate.mjs` / `tauri-build-retry.sh` | ✅ | 均有对应测试 |
| `Docs/` | 文档库（本文件 + `README.md` 总索引） | ✅ | |
| `.github/` | CI（`ci.yml` 五 job）+ `release.yml`（tag/手动触发发布） | ✅ | |
| `release-packages/` | **当前版本**发布产物暂存区 | ❌ | 按《双远程发布流程》SOP 使用，不是历史档案馆 |
| `.cnb-worktree/` | CNB 双远程发布的隔离 worktree（`cnb-main` 分支） | — | **禁止手动删除**，见 §四 |
| `target/` | cargo 构建缓存 | ❌ | 各子目标角色见 §三 |
| `node_modules/` `frontend/dist/` | 依赖与构建产物 | ❌ | 可随时重建 |

### 为什么测试分散在两处（且不要合并）

- `tests/`（仓库根）—— JS 契约测试，用 `node:test` 直接跑源码级断言（版本一致性、文档 schema、发布门禁、桥接模块）；
- `src-tauri/tests/` —— Rust 集成测试，Cargo 约定必须放在**对应 crate 内**才会被 `cargo test` 发现。

两者分属不同工具链（node vs cargo），是 workspace 项目的标准布局，搬动任何一边都会破坏构建约定。

## 二、测试数据的分布与生命周期（仓库内不落测试数据）

| 测试组 | 位置 | 数量 | 临时数据去向 |
|---|---|---|---|
| JS 前端契约 | `tests/frontend/` | 12 个文件 | 只读仓库源码 + 系统 tmpdir（`ew-checkver-` / `ew-docschema-` 前缀，`mkdtemp` 自动回收） |
| JS 脚本门禁 | `tests/scripts/` | 3 个文件 | 同上 |
| Rust 集成 | `src-tauri/tests/` | 35 个二进制 + `common/` 脚手架 | `common/mod.rs::temp_dir()` → 系统临时目录 `ew_it_<tag>_<pid>_<纳秒>`，并行安全，**绝不接触用户真实数据库与真实 WebDAV 目录** |

CI（`.github/workflows/ci.yml`）五个 job：`version`（版本一致性）→ `schema-docs`（文档 schema 护栏 + 脚本测试）→ `frontend`（依赖护栏 + 桥接测试）→ `backend`（`cargo test -p easy-writing-core -p easy-writing-frontend`）→ `webdav`（真实服务端集成）→ `performance`（`--ignored` 性能门禁）。

本地运行：`pnpm test`（= `test:frontend` + `test:scripts` + `test:backend`）。

## 三、构建产物与缓存（全部 gitignore，可重建）

`target/` 各子目标角色与去留原则（2026-11-03 整理后仅保留 `release` 与 `aarch64-apple-darwin`）：

| 子目录 | 角色 | 整理前 | 处置 |
|---|---|---|---|
| `debug/` | 日常 `cargo build/test` 增量缓存 | 45 GB | **已清**（纯缓存，膨胀主因） |
| `wasm32-unknown-unknown/` | 前端 wasm 构建缓存 | 5.4 GB | **已清** |
| `x86_64-pc-windows-msvc/` | Windows 交叉编译缓存 | 2.7 GB | **已清**（需要时重建） |
| `wasm-bindgen/` `doc/` `tmp/` | 零星缓存 | ~105 MB | **已清** |
| `release/` | release 构建，**含可运行 `bundle/macos/Easy-writing.app`** | 2.4 GB | **保留**（当前 dev 运行实例） |
| `aarch64-apple-darwin/` | `--target aarch64-apple-darwin` 产物 | 705 MB | **保留**（发布构建路径） |

`frontend/dist/`：trunk 前端构建输出（11MB wasm），陈旧产物已于整理时删除，`trunk build` 重建。

`release-packages/`：**只放当前发布版本**的暂存产物（DMG / 便携 zip / Windows zip）。历史版本（0.1.0–0.3.5，共 23 个文件 ~130MB）已于整理时移除，仅留 0.3.6 一套作参考；正式产物以 GitHub/CNB Release 为准。

### 活库数据警示（历史遗留，已在本次清理中消除）

手种行使用非 UUID 主键（`vol-1`、`ch-1`、`wv-1`、`plot-1`、`char-1`），与 App 正常创建的 UUID 行混存，曾导致「DB 有行但 UI 为空」的误判。清理后活库仅保留 1 份《绍宋》测试导入（487 章 / 254,372 行词库），用于长篇性能验证；不再需要时可在 App 内删除。

## 五、整理原则（本次确立，后续遵守）

1. **仓库内不落测试数据**：所有测试写系统临时目录（`ew_it_*` / `ew-checkver-*` / `ew-docschema-*` 前缀），见 `src-tauri/tests/common/mod.rs` 的约定。
2. **构建产物与缓存一律 gitignore**：`target/`、`frontend/dist`、`node_modules`、`release-packages` 均不入库。
3. **`release-packages/` 是暂存区不是档案馆**：历史版本产物以远端 Release 为准，本地只留当前版本。
4. **`.cnb-worktree` 是基础设施**：删除它会破坏双远程发布身份隔离流程。
5. **文档宣称附带实测证据**：目录规模、清理量级均按整理当日实测记录（见 `current-state-map.md` 同期更新）。
