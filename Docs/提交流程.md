# 提交流程（双远程）

本仓库同时推送两个远程：

| 远程 | 地址 | 用途 |
|---|---|---|
| `origin` | `git@github.com:orderye/Easy-writing.git` | GitHub 主仓 |
| `cnb` | `https://cnb.cool/toroyxxx/Easy-writing.git` | CNB 镜像 |

## 关键约定：CNB 用隔离 worktree 提交

**GitHub 在主目录提交，CNB 在 `.cnb-worktree` 提交。**
原因是两者的提交身份不同：

| 位置 | 分支 | 作者邮箱 |
|---|---|---|
| 主目录 | `main` | `orderye@qq.com`（来自 `~/.gitconfig`） |
| `.cnb-worktree` | `cnb-main` | `3WJRP74JzJLZlOYQ8b7VcB+cnb.dgyOUWMigHA@noreply.cnb.cool` |

worktree 的身份覆盖只改了 `email`，`name` 继承全局的 `orderye`。
配置位于 `.git/worktrees/-cnb-worktree/config.worktree`，内容为：

```ini
[user]
	email = 3WJRP74JzJLZlOYQ8b7VcB+cnb.dgyOUWMigHA@noreply.cnb.cool
[branch "cnb-main"]
	remote = cnb
	merge = refs/heads/main
[push]
	default = upstream
```

`push.default = upstream` 意味着在 worktree 里**直接 `git push` 就会推到 `cnb/main`**，
不需要显式指定远程。

## 标准流程

```bash
# 1. GitHub（主目录）
cd "/Volumes/WD Drive/项目/Easy-writing · 小说工作台"
git add <paths>            # 按路径显式暂存，避免误提交临时文件
git commit -F - <<'MSG'
提交信息
MSG
git push origin main

# 2. CNB（隔离 worktree，身份自动为 CNB 邮箱）
cd ".cnb-worktree"
# 需要把主目录的改动同步过来（见下节）
git commit -am "..."
git push
```

## 两个工作区的关系（重要）

`.cnb-worktree` 与主目录是**同一仓库的两个工作区、不同分支**：

- 主目录：`main`（跟踪 `origin/main`）
- worktree：`cnb-main`（跟踪 `cnb/main`）

它们**不会自动同步**。在主目录提交后，worktree 的工作区仍是旧内容，
直接 `git -C .cnb-worktree commit -am` 不会包含新改动。

两种同步方式：

```bash
# 方式 A：让 cnb-main 快进到 main，两边内容一致（推荐）
git -C .cnb-worktree merge --ff-only main
# 此时 cnb-main 与 main 指向同一个提交，提交身份沿用 main 的作者

# 方式 B：在 worktree 里重新提交一次，产生独立提交
git -C .cnb-worktree merge main --no-commit   # 或 cherry-pick
git -C .cnb-worktree commit -m "..."
# 此时 CNB 上是独立的提交，作者为 CNB 邮箱，但 hash 与 GitHub 不同
```

**选择依据**：若在意 CNB 上显示 CNB 身份，用方式 B；若只要求两边内容一致，
用方式 A 更省事（但 CNB 上的作者会与 GitHub 相同）。

## 校验当前状态

```bash
# 四个 ref 是否一致
git rev-parse --short main cnb-main
git ls-remote origin main | cut -c1-7
git ls-remote cnb main | cut -c1-7

# worktree 生效身份
git -C .cnb-worktree var GIT_AUTHOR_IDENT
```

## 注意

1. **不要在主目录直接 `git push cnb main`**——那样提交的作者是 GitHub 身份，
   绕过了 worktree 的 CNB 身份约定。
2. worktree 里 `git add -A` 前先 `git status` 复核，避免把构建产物纳入。
3. 临时提交信息文件不要落在仓库内（用 `git commit -F -` 从 stdin 读）。
