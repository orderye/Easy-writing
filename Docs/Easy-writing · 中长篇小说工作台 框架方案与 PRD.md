# Easy-writing · 中长篇小说工作台 框架方案与 PRD

Oct 14, 2026 · @Roy

## 1. 产品概述

Easy-writing（中长篇小说工作台）是一个把设定、大纲、章节正文和多个 AI agent 的协作放进同一界面的写作工具，面向独立写中长篇小说的个人作者，以本地桌面应用的形式使用。

**核心价值**

- 设定自己长出来：世界观、角色、剧情、大纲可以一开始留空，写正文时由 AI 提炼整理，你确认后才入库；随时在左栏可查可改，写正文时不必翻文档。
- 结构清晰：作品按「卷 → 章」组织，右栏管理结构，中间只管写。
- AI 贴身、多 agent 分工：世界观、角色、剧情、大纲、卷章各有一个预设 agent，可分别接入不同的大模型 API；正文下方有对话框，各设定输入框有一键「AI 修饰」（润色并补全已写内容），对话框只作用于正文，并严格按设定写作，与设定冲突时先问你、你确认后才改设定。
- 数据自主：本地桌面应用，数据存在本机；自带大模型 API，整库经 WebDAV 备份，内容不依赖第三方账号。

**范围**

| 类别 | 内容 |
| --- | --- |
| MVP 内 | 作品管理、左栏四类设定、右栏卷目/章节管理、写作台（富文本，左右栏可隐藏）、AI 辅助对话（严格按设定写作）、多 agent（预设 agent 与各自绑定的 API）、AI 修饰、手动提炼本章、设置（大模型 API、WebDAV）、手动保存与自动保存 |
| 暂不做 | 多人协作、登录与账号体系、发布/投稿、排版导出（可后续加 Markdown/Word 导出）、Linux、移动端与网页版 |

**假设**：一部作品含多卷、每卷多章，按中长篇的体量设计；只有一卷时，界面把卷目折叠为单层即可。

## 2. 整体框架方案

Easy-writing 是一个本地桌面应用（先支持 Windows 和 macOS），分「界面层 + 本地服务层 + 本地数据库」三部分：界面层负责编辑和展示，本地服务层负责数据存取并代发大模型和 WebDAV 请求，全部数据存在本机的一个 SQLite 文件里。

### 2.1 界面布局

&#91;embedded content: 界面布局 · 三栏加写作台三层\]

左栏放四类设定，右栏放保存与卷目、章节，中间是写作台；带「AI 修饰」标记的六处输入框各有一个修饰按钮；左右两栏都可手动隐藏。

### 2.2 系统架构

&#91;embedded content: 系统架构 · 前端、后端、存储与外部服务\]

界面层只和本地服务层通信；AI 网关和同步服务分别代发大模型与 WebDAV 请求，密钥因此只留在服务层，不进入界面层，也不写进数据库。

### 2.3 模块划分

| 层 | 模块 | 职责 |
| --- | --- | --- |
| 界面层 | 工作台外壳 | 顶部小说名与保存按钮、三栏布局、左右栏的隐藏与展开、全局状态与未保存提示 |
| 界面层 | 设定模块 | 世界观、角色设定、剧情梳理、大纲管理的列表与编辑；可以为空，由 AI 提炼逐步填充 |
| 界面层 | 结构模块 | 卷目管理、章节管理、拖拽排序与状态 |
| 界面层 | 写作台 | 卷目-章节条、富文本编辑器、AI 对话框（只作用于正文） |
| 界面层 | AI 修饰组件 | 一个通用组件，六处输入框复用：按钮、对比弹层、采用 / 重试 / 放弃 |
| 界面层 | 提炼确认面板 | 展示 AI 从正文提炼出的候选设定，逐条采纳 / 编辑 / 忽略 |
| 界面层 | 冲突提示卡 | 对话框生成内容与设定冲突时弹出，列出冲突点和涉及的设定，由用户选择处理方式（见 4.3） |
| 界面层 | 设置页 | 大模型 API、预设 agent 及其接口绑定、WebDAV、写作偏好 |
| 服务层 | 内容服务 | 作品、卷、章、设定、对话记录的增删改查与排序；图片文件的存取；提炼候选的去重合并与采纳；设定改动的留档 |
| 服务层 | Agent 调度 | 按模块选出对应 agent，取它的提示词和绑定的接口，再交给 AI 网关；提炼时让多个 agent 并行工作 |
| 服务层 | AI 网关 | 统一两种模型协议，装配上下文，流式转发，错误归一化；承担对话、修饰、提炼三类调用 |
| 服务层 | 设定一致性检查 | 对话框和选中文字操作生成前后，对照设定找冲突；有冲突时不写入正文，交给冲突提示卡 |
| 服务层 | 同步服务 | 数据库一致性快照、WebDAV 整库上传、下载恢复、本地快照；图片文件夹的增量上传与补下载 |
| 服务层 | 配置与密钥 | 密钥存系统钥匙串，连接测试 |
| 存储 | 数据库与图片文件夹 | 本机 SQLite 文件（见第 6 节）；图片单独存在应用数据目录的图片文件夹 |

技术栈不在本文限定：桌面壳选用 Tauri：服务层运行在 Tauri 的原生核心进程里，界面层是系统 WebView 中的前端（框架不限），两者通过 Tauri 命令通信；数据库用 SQLite，图片存在应用数据目录的图片文件夹。

## 3. 前端功能需求

界面分三栏：左栏管设定，右栏管结构，中间专心写作；顶部左侧是小说名，右侧是保存按钮。左栏和右栏都可以手动隐藏（点栏边缘的按钮折叠或展开），隐藏后写作台占满宽度，下次打开时保持上次的状态（P0）。右栏隐藏时，保存按钮移到写作台顶部右侧，保持可用；左栏隐藏时，小说名显示在写作台顶部。优先级：P0 为 MVP 必做，P1 为紧随其后。

### 3.1 左栏：设定区

左栏最上方显示小说名（点击可行内改名），其下是四个设定模块，点击切换，内容在左栏内展开编辑。四个模块一开始可以是空的：不必先写设定，开始写正文后，AI 会提炼出候选条目，用户确认后才进入对应模块（见 4.2）；手动新增和修改始终可用。每个模块由一个预设 agent 负责修饰与提炼（见 5.2）。条目很多时，各模块支持搜索和分组折叠（P1）。

| 模块 | 用途 | 主要内容 | 交互 | 优先级 |
| --- | --- | --- | --- | --- |
| 世界观 | 时代、地理、规则、术语 | 多条目，每条含标题和正文，可分组 | 增删改、拖拽排序、AI 修饰 | P0 |
| 角色设定 | 角色卡 | 姓名、别名、身份、外貌、性格、背景、目标、人物关系 | 列表加详情、AI 修饰 | P0 |
| 剧情梳理 | 主线、冲突、伏笔与回收 | 事件条目，带「已埋 / 已回收」状态，可关联章节 | 增删改、状态切换、AI 修饰 | P0 |
| 大纲管理 | 全篇梗概、卷纲、章纲 | 三层提纲：全篇梗概存于作品，卷纲即卷简介，章纲即章摘要，与右栏卷目、章节是同一份内容 | 编辑提纲、跳转到对应章节、AI 修饰；在这里改动会同步到右栏，反之亦然 | P0 |

### 3.2 右栏：保存与结构

- **保存按钮**（最上方，P0）：手动保存；状态显示「已保存 / 有未保存修改 / 保存中 / 保存失败」；快捷键 Ctrl/Cmd+S。另有自动保存，间隔在设置里可调（P0）。
- **卷目管理**（P0）：新建、重命名、删除、拖拽排序、折叠；每卷有简介输入框，带 AI 修饰按钮；卷简介就是大纲里的卷纲，两处是同一份内容。
- **章节管理**（P0）：在卷下新建、重命名、删除、拖拽排序（可跨卷移动）；显示字数和状态（草稿 / 修改中 / 定稿）；章节很多时可按标题搜索、按状态筛选（P1）；每章有摘要输入框，带 AI 修饰按钮；章摘要就是大纲里的章纲，两处是同一份内容。
- 删除卷或章节时二次确认，并进入回收站，可恢复（P1）。

### 3.3 中间：写作台

写作台自上而下分三层：

1. **卷目-章节条**：显示当前位置，如「第一卷 › 第三章」，点击可下拉快速切换，两侧有上一章 / 下一章，右端有「提炼本章」按钮，用于触发 AI 提炼（P0）。
2. **正文编辑区**：富文本编辑，支持标题、加粗、斜体、字体颜色、对齐、引用、分隔线、列表、图片和撤销重做；底部状态栏显示本章字数和保存状态（P0）。选中文字后弹出 AI 操作：续写、润色、扩写、缩写（P1）。
3. **AI 辅助对话框**：可折叠、可拖动调整高度；对话对象固定为「写作助手」。每次发送都会自动带入设定（世界观、角色设定、剧情梳理、大纲，以及卷目、章节内容）作为必须遵守的依据，不可关闭：条目不多时全量带入；条目很多时，带入全部条目的名称与摘要索引，再按当前章节自动选取相关条目的完整内容（出场角色、涉及的世界观、未回收的伏笔、本章及前后章的章纲与摘要）；用户还可勾选额外带入其他章节作参考。对话框只作用于正文编辑区：可以修改选中的内容、重写整段或整章，也可以按指令直接创作新内容；结果先预览，点「插入正文 / 替换选中」才写入，也可复制（P0）。与设定冲突时的处理见 4.3。

### 3.4 AI 修饰提示词按钮

世界观、角色设定、剧情梳理、大纲管理、卷目管理、章节管理这六处的输入框，右上角各有一个「AI 修饰」按钮。大纲管理里的卷纲、章纲与卷目、章节里的简介、摘要是同一份内容，在哪里修饰，结果都一样。每个输入框的修饰由所属模块的预设 agent 完成，卷目与章节共用「卷章 agent」（见 5.2）。

「AI 修饰」的含义是润色并补全输入框里已写的内容。流程：用户在输入框写下草稿或要点，点击按钮，AI 修饰后的版本与原文并排显示，用户选择「采用 / 重试 / 放弃」，采用后才写回输入框，原文可撤销（P0）。

| 输入框 | 修饰方向（默认） |
| --- | --- |
| 世界观条目 | 补全设定细节，统一术语，保持与已有世界观不矛盾 |
| 角色卡字段 | 丰富人物刻画，使性格、背景、目标相互呼应 |
| 剧情条目 | 理清因果，指出缺口或待回收的伏笔 |
| 大纲（全篇梗概、卷纲、章纲） | 让节奏和起承转合更明确 |
| 卷简介（即卷纲） | 提炼本卷主题与走向 |
| 章摘要（即章纲） | 精炼为一两句话，兼作章纲 |

每处的修饰提示词模板可在设置里查看和自定义（P1）。

## 4. AI 能力设计

AI 有三个入口——正文下方的对话框、各输入框的修饰按钮，以及从正文自动提炼设定——共用同一套「上下文装配 + 模型调用」；所有 AI 输出都先展示给用户，确认后才写入作品。

### 4.1 对话、修饰与上下文

| 入口 | 触发 | 送给模型的内容 | 输出 | 写回方式 |
| --- | --- | --- | --- | --- |
| 对话框 | 用户发送消息 | 用户消息、设定（索引加相关条目）、前情摘要与当前章节、近几轮对话、写作助手的提示词 | 流式文本；与设定冲突时改为冲突提示 | 点「插入正文 / 替换选中」；遇冲突须先确认 |
| 修饰按钮 | 点击输入框旁按钮 | 输入框当前内容、所属 agent 的提示词与修饰模板、相关设定 | 润色并补全后的文本 | 对比后点「采用」 |
| 提炼设定 | 点「提炼本章」 | 本章正文、已有设定的名称与摘要索引；各 agent 只提炼自己负责的类型 | 候选条目（新增或更新） | 在待确认面板逐条采纳 / 编辑 / 忽略 |
| 选中文字操作（P1） | 选中正文后选操作 | 选中片段及前后文、操作类型、设定（索引加相关条目） | 改写结果；与设定冲突时改为冲突提示 | 对比后点「采用」；遇冲突须先确认 |

**上下文装配**：按下列顺序拼成一次请求，超出模型上下文长度时从后往前裁剪。

1. 系统提示词：当前 agent 的身份与要求、作品名、文风要求（来自该 agent 的提示词，未设置时用默认提示词）。
2. 设定：世界观、角色设定、剧情梳理、大纲，以及卷目、章节内容。对话框和选中文字操作必带，不可关闭；条目较多时，先带全部条目的名称与摘要索引，再按当前章节选取相关条目的完整内容，并保留姓名、世界规则、已发生的关键事件等硬性约束；设定为空时只带当前章节。
3. 前情与当前章节：前几章的章摘要、上一章结尾，加当前章节全文或选中片段。
4. 对话历史。

**体验要求**

- 流式输出，可随时中断，失败可一键重试。
- 错误给出可操作的提示：密钥无效、额度不足、网络超时、模型不支持。
- 对话记录随作品保存，可按章节筛选（P1）。
- 修饰模板和系统提示词支持用户自定义，设置里提供「恢复默认」。

### 4.2 AI 自动提炼设定

用户可以不写任何设定就开始写正文：AI 从章节正文里提炼世界观、角色、剧情和大纲，整理成「待确认」候选，用户采纳后才进入对应模块。

**提炼流程**

1. 触发：在写作台点「提炼本章」；设置里可打开「保存章节后自动提炼」（P1，默认关闭）。
2. 输入：本章正文，加上已有设定的名称与摘要索引，用来识别同一角色、同一设定。世界观、角色、剧情、大纲四个 agent 并行工作，各自只处理自己负责的类型，使用各自绑定的接口。
3. 输出：结构化候选，每条标明类型（世界观 / 角色 / 剧情 / 章摘要）、动作（新增 / 更新已有条目）、来源章节和原文依据片段。
4. 去重合并：按名称和别名与已有条目比对；同一角色的新信息作为「更新」候选，不新建重复条目。
5. 确认：候选集中显示在待确认面板，也在左栏对应模块里带「待确认」标记；可逐条采纳、编辑后采纳或忽略，也可「全部采纳」。
6. 记录：每章记住最近一次提炼时的正文指纹，正文没变就不重复提炼；已忽略的候选不再重复出现。

**提炼内容**

| 类型 | 负责的 agent | 提炼什么 | 采纳后写入 |
| --- | --- | --- | --- |
| 世界观 | 世界观 agent | 时代、地点、规则、术语 | 世界观条目 |
| 角色 | 角色 agent | 新出现的人物、别名、外貌与性格、关系变化 | 角色卡（新增或补充） |
| 剧情 | 剧情 agent | 事件、冲突、伏笔，以及伏笔是否在本章被回收 | 剧情条目（含状态更新） |
| 章摘要与大纲 | 大纲 agent | 本章一两句话摘要，必要时补全卷简介 | 章摘要、卷简介（即大纲） |

**要求**

- AI 提炼的内容一律先作为候选，不直接改动已有设定；采纳后的条目标注来源章节，可跳回原文。
- 只送本章正文和设定索引，不送全书，控制上下文长度和调用成本。
- 提炼失败或结果为空时给出明确提示，不影响写作；某个 agent 的接口失败时，其他 agent 的结果照常显示。

### 4.3 对话框：只作用于正文，严格遵循设定

对话框（写作助手）和选中文字操作只作用于正文编辑区，并且必须严格按设定写作：世界观、角色设定、剧情梳理、大纲，以及卷目、章节的内容，都是硬性依据。

**可做的事**

| 方式 | 含义 | 结果 |
| --- | --- | --- |
| 修改 | 按指令改动选中的文字或当前段落 | 差异预览，采用后替换 |
| 重写 | 重写选中范围、整段或整章，保持设定与剧情走向 | 新版本预览，采用后替换 |
| 直接创作 | 按指令，或按章纲、章摘要，写出新内容（续写、补写、新写） | 新内容预览，采用后插入光标处 |

**边界**

- 只改动正文：对话框不会直接新增、修改或删除任何设定、卷目、章节的内容。
- 每次发送都带入设定作为依据（条目多时按相关性选取，见 4.1），用户不能关闭。
- 想改设定，只能走下面的冲突确认流程。

**冲突处理**

1. 检查：生成前后，AI 对照设定检查用户指令和生成内容，找出矛盾，例如角色性格、世界规则、已发生的事件、大纲安排；设定很多时，按涉及的角色、地点、事件逐条检索相关设定来核对，不只看带入上下文的那部分。
2. 暂停：发现冲突时不写入正文，弹出冲突提示卡，说明冲突点、涉及的设定条目（模块与条目名）和依据。
3. 选择：卡片给出三个选项——「修改设定后继续」（附 AI 拟好的设定改动，可先编辑）、「换一种不冲突的写法」、「取消」。
4. 确认：只有用户选「修改设定后继续」并确认改动内容后，才会修改对应的世界观、角色设定、剧情梳理、大纲、卷目或章节；改动前后的内容留档，可撤销（P1）。
5. 继续：设定改完后，AI 按新设定继续生成，结果仍要用户点采用才写入正文。

冲突涉及多处设定时，一张卡片逐条列出，用户逐条确认。

**要求**

- 用户确认之前，不对任何设定做写入。
- 冲突提示要给出依据（哪条设定、哪句话矛盾），让用户判断得出。
- 检查有误报或漏报的可能，用户始终可以选「换一种写法」或「取消」。

## 5. 设置

设置页放三类内容：大模型 API 接口、预设 agent（各自绑定接口）和 WebDAV，外加少量写作偏好；入口建议放在左栏底部的齿轮。两类连接都提供「测试连接」按钮，并把密钥类字段掩码显示。

### 5.1 大模型 API 接口

| 字段 | 说明 | 优先级 |
| --- | --- | --- |
| 接口协议 | OpenAI 兼容 / Anthropic 兼容，两种协议覆盖多数服务商 | P0 |
| Base URL | 接口地址，可填第三方中转 | P0 |
| API Key | 存系统钥匙串，不写入数据库；界面掩码显示，因此不会随整库上传 | P0 |
| 模型名称 | 手动填写，可选「拉取模型列表」 | P0 |
| 生成参数 | temperature、最大输出长度、是否流式 | P0 |
| 多套配置 | 保存多组接口，供各 agent 分别绑定，也可一键切换默认接口 | P0 |
| 测试连接 | 发一条最小请求，返回成功或具体失败原因 | P0 |

### 5.2 多 agent 设置

Easy-writing 采用多 agent 分工：每个模块对应一个预设 agent，每个 agent 可以单独绑定一套大模型接口——比如世界观用一个模型，剧情梳理用另一个。

| agent | 负责的模块 | 主要任务 |
| --- | --- | --- |
| 世界观 agent | 世界观 | 修饰世界观条目；提炼时代、地点、规则、术语 |
| 角色 agent | 角色设定 | 修饰角色卡；提炼人物、别名与关系变化 |
| 剧情 agent | 剧情梳理 | 修饰剧情条目；提炼事件、冲突、伏笔与回收 |
| 大纲 agent | 大纲管理 | 修饰全篇梗概、卷纲、章纲；提炼章摘要和卷简介 |
| 卷章 agent | 卷目管理、章节管理 | 从卷目、章节入口修饰卷简介和章摘要 |
| 写作助手 | 写作台对话框 | 修改、重写、直接创作正文，严格遵循设定；是对话框的固定对象，不绑定设定模块 |

**每个 agent 的配置**

| 配置项 | 说明 | 优先级 |
| --- | --- | --- |
| 绑定的接口 | 从 5.1 的接口里选一套；未绑定时使用默认接口 | P0 |
| 系统提示词 | 该 agent 的身份、口吻和要求；预设有默认值，可修改、可恢复默认 | P0 |
| 生成参数 | 覆盖所绑接口默认的 temperature 与最大输出长度 | P1 |
| 启用开关 | 关闭后，提炼时跳过该 agent | P1 |

**调用规则**

- 点某个输入框的「AI 修饰」，由该输入框所属模块的 agent 处理；同一份卷简介、章摘要，在大纲里点用大纲 agent，在卷目、章节里点用卷章 agent。
- 点「提炼本章」，世界观、角色、剧情、大纲四个 agent 并行工作，各自处理自己的类型。
- 写作台对话框固定与写作助手对话，只作用于正文，规则见 4.3。
- agent 所绑的接口被删除或失效时，提示用户并回退到默认接口。
- MVP 只提供上面六个预设 agent，不支持自建；自建 agent 留作后续。

### 5.3 WebDAV 接口

| 字段 / 功能 | 说明 | 优先级 |
| --- | --- | --- |
| 服务器地址、用户名、密码、远程目录 | 密码建议使用应用专用密码；存系统钥匙串，不写入数据库，不随整库上传 | P0 |
| 立即备份 | 先把图片文件夹中新增的图片上传，再对数据库做一致性快照并压缩，把整个库文件上传到远程目录；库文件名含时间，不覆盖旧备份 | P0 |
| 从云端恢复 | 按时间倒序列出远程备份，由用户手动选择；恢复前提示将替换整个本地库，并自动留一份本地快照；恢复后补下载本机缺失的图片；在新设备上恢复后需重新填写密钥 | P0 |
| 图片备份 | 图片文件夹与数据库分开处理：按文件增量上传到远程图片目录，文件名为内容哈希，只传新增的 | P0 |
| 自动备份 | 按设定的间隔（如每次退出应用时）异步上传，失败只提示不阻塞写作 | P1 |
| 备份范围 | 数据库：所有作品的设定、卷目、章节、对话记录、提示词模板，以及不含密钥的配置；图片：整个图片文件夹 | P0 |

### 5.4 其他偏好

- 自动保存间隔、编辑器字号和行距、保存章节后是否自动提炼（P1，默认关闭）。
- 各处修饰模板的自定义和恢复默认（P1）；各 agent 的系统提示词见 5.2。

模型请求和 WebDAV 请求均由本地服务层代发，密钥只在服务层使用，不暴露给界面层。

## 6. 数据库设计

使用本机 SQLite：单用户桌面应用，整个库就是一个文件，正好用于 WebDAV 整库上传。备份时先用 SQLite 的备份接口生成一致性快照再上传，不直接复制正在写入的库文件。图片不在库内，另存于图片文件夹，备份时另行处理（见 5.3）。

**通用约定**：主键用 UUID；每张业务表带 created\_at、updated\_at、deleted\_at（软删除，对应回收站）；有序数据用 sort\_order 字段；密钥（API Key、WebDAV 密码）不入库，只存系统钥匙串；章节列表查询不读取 content，只读 summary、word\_count 等轻量字段，正文按章单独加载；novel\_id、volume\_id、sort\_order 等常用查询字段建索引。

### 6.1 作品与内容表

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| novel | id、title、synopsis | 作品，对应左栏顶部的小说名；synopsis 为全篇梗概，是大纲的最上层 |
| volume | id、novel\_id、title、summary、sort\_order | 卷，属于一部作品；summary 即卷简介，也是大纲里的卷纲 |
| chapter | id、novel\_id、volume\_id、title、summary、content、content\_plain、word\_count、status、extracted\_hash、sort\_order | 章；summary 即章摘要，也是大纲里的章纲；content 存富文本（编辑器文档 JSON，图片引用 asset），content\_plain 为纯文本，供 AI 与字数统计使用；extracted\_hash 记录最近一次提炼时的正文指纹；status 取 草稿 / 修改中 / 定稿 |
| chapter\_revision | id、chapter\_id、content、created\_at | 章节历史版本（P1），手动保存时记录 |
| asset | id、novel\_id、name、mime、rel\_path、size、hash、created\_at | 正文里的图片；图片文件单独存在应用数据目录的图片文件夹，库内只存相对路径和内容哈希，备份时与数据库分开处理；存入前压缩 |

### 6.2 设定表

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| worldview\_entry | id、novel\_id、group\_name、title、content、origin、source\_chapter\_id、sort\_order | 世界观条目；origin 取 手动 / AI 提炼，source\_chapter\_id 为来源章节 |
| character | id、novel\_id、name、aliases、profile、origin、source\_chapter\_id、sort\_order | 角色卡；profile 为 JSON，存外貌、性格、背景、目标等，字段可扩展 |
| character\_relation | id、novel\_id、from\_id、to\_id、label | 人物关系（P1） |
| plot\_item | id、novel\_id、title、content、kind、status、chapter\_id、origin、sort\_order | 剧情条目；kind 取 主线 / 冲突 / 伏笔；status 取 已埋 / 已回收；chapter\_id 可空；origin 同上 |

### 6.3 AI 与设置表

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| agent | id、key、name、system\_prompt、llm\_profile\_id、params、enabled | 预设 agent；key 取 世界观 / 角色 / 剧情 / 大纲 / 卷章 / 写作助手；llm\_profile\_id 指向绑定的接口，可空（为空时用默认接口） |
| chat\_session | id、novel\_id、chapter\_id | 对话会话，chapter\_id 可空，用于按章筛选；对话对象固定为写作助手 |
| chat\_message | id、session\_id、role、content、created\_at | 对话消息，role 取 用户 / 助手 |
| extraction\_candidate | id、novel\_id、chapter\_id、agent\_id、kind、action、target\_id、payload、evidence、status、created\_at | AI 提炼的待确认候选；agent\_id 为产出它的 agent；kind 取 世界观 / 角色 / 剧情 / 章摘要；action 取 新增 / 更新；target\_id 为被更新的已有条目；payload 为候选内容 JSON；evidence 为原文依据；status 取 待确认 / 已采纳 / 已忽略 |
| setting\_change | id、novel\_id、chapter\_id、target\_type、target\_id、before、after、reason、created\_at | 对话框冲突确认后对设定的改动，留下改动前后的内容，供撤销（P1）；target\_type 取 世界观 / 角色 / 剧情 / 大纲 / 卷 / 章；reason 为冲突说明 |
| prompt\_template | id、scope、content、is\_default | 各处修饰模板与提炼模板；agent 的系统提示词放在 agent 表 |
| llm\_profile | id、name、protocol、base\_url、key\_ref、model、params、is\_default | 大模型接口配置，可被多个 agent 绑定；key\_ref 指向系统钥匙串里的密钥，密钥本身不入库 |
| webdav\_config | id、url、username、pwd\_ref、remote\_dir | WebDAV 配置；pwd\_ref 指向系统钥匙串里的密码 |
| app\_setting | key、value | 自动保存间隔、字号、是否自动提炼、左右栏是否隐藏等偏好 |

**关系**：novel 一对多 volume，volume 一对多 chapter；设定类表、asset 和 chat\_session 都挂在 novel 下；agent 通过 llm\_profile\_id 绑定接口，extraction\_candidate 记录产出它的 agent；setting\_change 记录对话框冲突确认后的设定改动；plot\_item 和 extraction\_candidate 可指向具体章节；大纲不单独建表，由 novel.synopsis、volume.summary、chapter.summary 三层合成。

**备份与导出**：WebDAV 备份是整库上传——先生成一致性快照，再上传整个库文件；恢复时先对本地库做快照，再用下载的库文件整体替换。密钥在系统钥匙串里、不在库内，因此不会被上传。图片文件夹另行同步：按内容哈希增量上传，先传图片再传库，恢复后补下载本机缺失的图片。单个作品的导出留作后续功能。

## 7. 非功能需求、里程碑与待确认

### 7.1 非功能需求

- **流畅**：切换章节和保存不卡顿；只加载当前章节正文，不一次读入全书；章节列表按卷折叠、长列表虚拟滚动；设定条目多时可搜索（P1）。
- **数据安全**：API Key 与 WebDAV 密码存系统钥匙串，不写入数据库；删除先进回收站；整库上传的文件不含密钥。
- **可靠**：自动保存；异常关闭后可恢复最近一次自动保存；AI 调用失败不影响写作。
- **兼容**：本地桌面应用，先支持 Windows 和 macOS；Linux 和移动端暂不适配。
- **可扩展**：设定模块和模型协议都能新增，不改动其他模块。

### 7.3 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 各家模型接口差异大 | 对话、修饰、提炼调用失败 | 先支持两种协议，统一适配层，提供「测试连接」 |
| 设定很多，上下文超长 | 请求失败或回答质量下降 | 提炼只送本章正文和设定索引；对话框先带设定索引，再按当前章节选取相关条目全文，并保留姓名、世界规则等硬性约束 |
| 冲突检查漏报或误报 | 正文与设定矛盾没被发现，或频繁打断写作 | 冲突卡片附设定依据；用户始终可选「换一种写法」或「取消」；检查提示词放在写作助手的配置里，可调整；设定很多时按涉及的角色、地点、事件检索相关设定来核对 |
| AI 提炼误判或重复 | 设定库被污染 | 候选先进待确认面板，逐条确认；按名称和别名去重；每条附原文依据 |
| 多个 agent 并行提炼 | 触发限流，调用费用上升 | 限制并行数；默认让各 agent 共用同一接口；某个 agent 失败不影响其他 agent |
| WebDAV 服务商行为不一致 | 备份或恢复失败 | 保存配置时先测试读写，失败给出明确原因 |
| 整库上传文件较大或中途中断 | 备份慢，或远程文件不完整 | 上传前先做一致性快照并压缩；先传临时文件，完成后再改名；失败可重试 |
| 图片与数据库备份不同步 | 恢复后正文里的图片缺失 | 先传图片再传库；恢复后校验引用，补下载缺失的图片 |
| 恢复时整体替换本地库 | 数据丢失 | 恢复前自动留本地快照并二次确认 |
| 多台设备各自备份 | 新内容被旧备份覆盖 | 备份文件名带时间、不覆盖；恢复时按时间列出，由用户手动选择 |
| 密钥泄露 | 被他人盗用额度 | 存系统钥匙串、界面掩码、不入库、不上传 |

### 7.4 已确认与待确认

**已确认**

| 事项 | 结论 |
| --- | --- |
| 应用名与定位 | Easy-writing，中长篇小说工作台 |
| 设定从哪来 | 世界观、角色、剧情、大纲可以一开始留空，写正文时由 AI 提炼整理（见 4.2） |
| 多 agent | 每个模块对应一个预设 agent，各 agent 可绑定不同的大模型接口（见 5.2） |
| agent 的划分 | 卷目管理、章节管理共用「卷章 agent」；在大纲里点修饰用大纲 agent，在卷目 / 章节里点用卷章 agent |
| 写作助手 | 保留，作为对话框固定的对话对象 |
| 对话框的作用范围 | 只作用于正文编辑区，可修改、重写、直接创作；必须严格按设定执行，冲突时先提示，用户确认后才改设定（见 4.3） |
| 「AI 修饰」的含义 | 润色并补全输入框里已写的内容 |
| 应用形态与平台 | 本地桌面应用，桌面壳用 Tauri，先支持 Windows 和 macOS |
| 界面 | 写作台的左栏、右栏都可手动隐藏；右栏隐藏时保存按钮移到写作台顶部右侧，左栏隐藏时小说名显示在写作台顶部 |
| 提炼的触发方式 | MVP 只做手动点「提炼本章」；保存后自动提炼放在 P1，默认关闭 |
| WebDAV 方式 | 整库上传；以时间区分多份备份，恢复时手动选择 |
| 图片存储与备份 | 图片单独存文件夹；备份时按文件增量上传到远程图片目录（文件名为内容哈希），先传图片、再传库 |
| 用户 | 单用户，无登录 |
| 正文编辑器 | 富文本：标题、加粗、斜体、字体颜色、对齐、引用、分隔线、列表、图片、撤销重做 |
| 大纲与简介、摘要 | 合并为同一份内容，不单独建大纲表 |

**待确认**

1. 设定被对话框改动后的撤销：本文会留档改动前后的内容，撤销功能列为 P1，是否需要提到 P0？
2. 体量预期：单部作品预计写到多少字、多少章？这决定章节列表、设定检索和备份体积要优化到什么程度。
3. 是否需要导入已有稿件（如 txt、docx），并批量提炼其中的设定？
