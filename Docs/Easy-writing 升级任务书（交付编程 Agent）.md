## 0. 使用说明与全局规则

**背景**：Easy-writing 是 Tauri 2 + Leptos 0.7(WASM) + Tiptap 2 + SQLite(rusqlite/r2d2/refinery) 的本地中长篇小说工作台。审核仅基于 README 与实施计划，未读源码，因此本文中的文件路径、表名均为假设，**必须先在仓库中核对**。

**全局规则（每个任务都适用）**

1. 开工前先通读 README、Docs/、src-tauri/src、frontend/、js/src、shared-types/、.github/workflows，产出「现状映射表」（本文假设 → 实际路径/表名），并附在第一个 PR 描述里。映射表不确认，不进入改动。
2. 标注「**先审计**」的任务：先输出审计结论（符合/不符合 + 代码证据），不符合才修改。
3. 数据库变更只能新增迁移文件（refinery，下一个可用版本号），不得修改已发布迁移；必须向后兼容旧库，并写迁移测试（旧库升级后数据不丢）。
4. 每个任务一个分支、一个 PR，提交信息用 Conventional Commits；GitHub 与 CNB 双远程按 Docs 中的提交流程与发布流程执行。
5. 必须通过 `pnpm test:frontend`、`pnpm test:backend`、`cargo test`；新增逻辑必须带测试；不得删除或放宽既有测试。
6. 新增第三方依赖需在 PR 描述中说明用途、许可证（须与 MIT 兼容）、体积影响。
7. 涉及备份、恢复、迁移、批量替换的改动，先在数据库副本上验证，禁止直接操作用户真实库。
8. 不做本文以外的重构；发现其他问题记录到 PR 的「后续建议」，不顺手修改。

**PR 描述模板**：变更摘要 / 涉及迁移 / 测试清单与结果 / 验收证据（截图或日志）/ 风险与回滚方式 / 后续建议。

**需要人工提供（Agent 不得编造）**：Apple/Windows 代码签名证书与 CI secrets、真实运行截图、可用的大模型测试 Key。

## 2. 第一类：文档同步

### T01 实施计划更新为现状版

- **目标**：文档与实现一致，避免后续协作按旧文档改错。
- **改动**：在《实施计划》补充 EPUB 导入、图库、词库、关系图谱(Force-Graph)、多作品看板、版本历史等已实现功能；新增「当前 Schema」章节，内容以 migrations 目录实际表结构为准（不得手写臆测）；更新 P1 状态；删除「导入 MVP 不含」等过时描述。

## 3. 第二类：高优先级

### T02 导出功能（txt / docx / epub）

- **目标**：作者可把作品导出用于投稿或发布。
- **改动**：新增命令 export\_novel；范围可选整书/多卷/多章；选项含卷章标题模板、段首缩进或空行、是否含图片、文件名；格式 txt、docx、epub。由 Tiptap JSON 在 Rust 端转换（docx、epub 可评估 docx-rs、epub-builder 等依赖并说明）；流式写文件，通过事件上报进度，支持取消，不得阻塞 UI；前端新增导出弹层。
- **验收**：300 章/百万字样例可导出且界面不卡死；导出字数与应用统计一致；docx 可被 Word 打开，epub 可被主流阅读器打开；含图片和不含图片两种场景均有测试；取消后不留半成品文件。

### T03 备份体积控制与保留策略

- **目标**：长期使用后备份不无限膨胀。
- **改动**：①章节版本快照按内容哈希去重，相同内容不新增；②每章快照设上限（默认 50，可配置），超限优先清理最旧的自动快照，保留手动快照；③远端保留策略：最近 N 份 + 每日 1 份 + 每周 1 份（默认值可配置），在新备份上传成功后才清理，且只处理符合 backup\_\*.db.gz 命名的文件；④清理提供 dry-run 预览（列出将删除项）；⑤备份压缩前执行 VACUUM（在备份副本上）。
- **验收**：重复保存同一内容不增加快照数；构造 60 份备份，策略执行后保留集合与规则一致；清理失败不影响已上传的新备份；有对应后端测试。

### T04 多设备覆盖保护（依赖 T03）

- **目标**：避免旧库覆盖新库。
- **改动**：生成并保存 device\_id；每次备份同时上传同名 .meta.json（device\_id、created\_at、库内最大 updated\_at、schema\_version、app\_version、sha256）。上传前读取远端最新 meta：若来自其他设备且晚于本地 last\_sync\_at，提示「继续上传 / 先恢复 / 取消」。恢复前强制校验 sha256，先在本地做保底快照，拒绝恢复 schema\_version 高于当前应用的备份。**先审计**：restore.rs 替换数据库文件前是否已关闭 r2d2 连接池或要求重启；不符合则修复。「退出自动同步」遇到冲突时不弹阻塞窗口，跳过并在下次启动提示。
- **验收**：模拟两个 device\_id 的 meta 能触发提示；sha256 不符时恢复被拒；恢复流程无「数据库被占用」类问题；有测试。

### T05 换设备后的密钥缺失处理

- **目标**：恢复备份后不出现静默失败。
- **改动**：启动和恢复完成后检查所有 llm\_profile.key\_ref 与 webdav\_config.pwd\_ref 在系统钥匙串中是否存在；缺失则在设置页显示「缺少密钥」徽标；AI 与 WebDAV 调用前预检，统一返回错误码 KEY\_MISSING 并引导到对应设置项；恢复完成后弹窗汇总需要补填的项。备份中不得包含任何密钥。
- **验收**：删除钥匙串条目后，调用返回 KEY\_MISSING 而非网络错误；徽标与引导可用；有测试（可对 keyring 做 trait 抽象后 mock）。

### T06 上下文装配透明度与预算

- **目标**：作者能看到并控制本次带入 AI 的设定。
- **改动**：重构 ai/context.rs。选取规则：角色（name 与 aliases）命中本章正文或用户指令、词库术语命中、最近 K 章摘要、被标记为「硬性」的设定始终带入。新增迁移：为世界观、角色、剧情条目增加 pinned(硬性) 字段；llm\_profile.params 增加 context\_window。通过 TokenEstimator trait 估算 token（中文先用字符系数，可替换），按文档化的优先级裁剪。返回 ContextManifest（条目类型、id、标题、入选原因、token、被裁剪项、预算）。前端对话框旁新增可折叠「本次上下文」面板，支持取消勾选或强制加入某条。
- **验收**：单元测试覆盖命中、别名、预算裁剪顺序；面板显示的清单与实际发送一致；取消勾选后该条不出现在请求中。

## 4. 第三类：中优先级

### T07 提炼成本与去重

- **改动**：①新增设置 extraction\_mode：parallel\_4（现状）与 single\_call（一次结构化 JSON 返回四类候选）；②去重增强：生成候选前先按归一化名称、别名匹配已有角色与候选池，命中则标记 possible\_duplicate\_of（新增列），提取面板提示「疑似同一人物，是否合并」，合并操作把新名称写入 aliases；③超长章节按段落分块提炼后合并结果（可配置阈值）。
- **验收**：构造「林舟/小舟」用例能被识别为疑似重复；single\_call 与 parallel\_4 的候选结构一致；有测试。

### T08 冲突检测结构化与可配置（依赖 T06 的 pinned）

- **改动**：检测输出固定为结构化 JSON：冲突点、关联设定（类型+id）、证据、置信度；设置项：前置检查开关、检查范围（仅硬性设定/全部）、置信度阈值；ConflictCard 展示依据，并提供「本章忽略此类提示」。保持现有 setting\_change 留档与撤销不变。
- **验收**：关闭前置检查后不再产生额外调用；低于阈值的结果不弹窗；有测试（用固定的模型返回样例）。

### T09 全书搜索与替换

- **改动**：新增迁移创建 FTS5 虚拟表（trigram 分词，覆盖章节标题与 content\_plain），用触发器同步并回填存量数据；**先确认**所用 SQLite 版本与 rusqlite 特性支持 trigram（≥3.34），不支持则在 Cargo 特性中解决并说明；查询不足 3 字符时回退 LIKE。命令 search\_chapters 返回命中片段与章节定位。替换流程：预览全部命中 → 勾选 → 执行；替换在 Tiptap JSON 的文本节点上进行，不得破坏样式标记与图片节点；执行前为受影响章节自动创建版本快照，支持整批撤销。
- **验收**：百万字样例搜索响应可接受；替换后富文本格式与图片保持；撤销后内容与替换前逐字一致；有测试。

### T10 伏笔看板（复用 T06 匹配逻辑）

- **改动**：新增伏笔总览视图：状态、埋设章节、距今章数（按卷章排序计算）、关联角色；超过阈值（默认 30 章，可配置）未回收的高亮；编辑器状态栏显示本章涉及的未回收伏笔数；支持一键跳转与「标记回收」（选择回收章节，必要时新增 resolved\_chapter\_id 迁移）。
- **验收**：章数计算跨卷正确；标记回收后状态与关联章节更新；有测试。

### T11 写作辅助

- **改动**：①每日字数统计表 daily\_stat（日期、作品、净增字数）与 daily\_goal 设置，状态栏显示进度；净增按保存时新旧字数差计算，导入与批量替换不计入；②专注/打字机模式（隐藏两栏、光标行居中），提供快捷键；③章节增加 pov\_character\_id（可空）与 story\_time，右栏支持按其筛选。
- **验收**：导入整书不会产生巨额「今日字数」；专注模式切换不销毁编辑器实例（沿用切章不销毁的原则）；有测试。

## 5. 第四类：安全与发布

### T12 Asset 协议与 CSP（先审计，M1 最先执行）

- **验收**：嵌套目录中的图片可显示；通过 `../` 构造的越界路径无法读取；输出审计结论与配置 diff。

- **验收**：Docs 中的发布流程已更新；提示中的哈希与 Release 附件一致。

### T14 打包与签名（依赖 T13）

- **改动**：**先审计** .github/workflows：现有构建矩阵与产物。新增 macOS Intel（x86\_64）或 universal 构建；补充 macOS 签名与公证、Windows 代码签名的 CI 步骤，读取 secrets（名称写入文档，值由人工配置）；无证书时 CI 仍须可跑通，并在 README 写明首次打开方式。
- **验收**：CI 产出 Apple Silicon 与 Intel 的 macOS 包及 Windows 包；未配置 secrets 时跳过签名但不失败；文档列出所需 secrets 清单。

### T15 WebDAV 明文传输警告

- **验收**：http 与 https 两种路径均有前端测试；本机回环地址是否豁免需在 PR 中说明取舍。

### T16 平台口径统一

- **验收**：全仓库搜索 Linux 相关表述，口径一致。
